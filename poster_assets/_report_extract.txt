[30|Normal] ABSTRACT
---
[31|Normal] The reason behind the development of this AI-based weather prediction system is the failure of generic weather apps to catch localized microclimates and neighborhood rainfall storms. Standard mobile weather services pull their data from regional airports spanning 15 to 25 kilometers away, averaging out the acute barometric pressure drops and humidity spikes that signal approaching precipitation. Furthermore, most internet-reliant weather devices fail during intense storms when local cell towers cut out. Our system resolves this through a modular dual-microcontroller and edge-server architecture.

An Arduino Uno acts as our dedicated sensor acquisition node, sampling ambient temperature and relative humidity from a DHT11 and precise atmospheric surface pressure from a Bosch BMP280 over I2C on a continuous 1-minute cycle. The Uno packages these clean readings into compact JSON telemetry and streams them across a direct UART serial bus to an ESP32 Wi-Fi gateway. The ESP32 forwards the telemetry packets directly over the local network via HTTP POST to a centralized Python Flask server running on a nearby laptop.

On the edge server, the incoming data is buffered into an in-memory 24-hour circular history to extract dynamic rate-of-change indicators: the 3-hour pressure drop (ΔP_3h), 6-hour pressure drop (ΔP_6h), and 3-hour humidity change (ΔRH_3h). A trained Scikit-Learn machine learning model (SGDClassifier with log-loss) processes these normalized physical features in real-time to forecast upcoming weather (Clear, Cloudy, or Rain) and calculates calibrated rain probabilities. If severe rain odds exceed 60%, the server issues a JSON alert response, providing real-time predictive warnings. Most importantly, the system is continuously self-training: every 6 hours, the edge server verifies past forecasts against real outdoor observations and executes online incremental training (model.partial_fit()), automatically recalibrating model weights to track shifting seasonal weather patterns without requiring manual retraining.

[35|Normal] Need for the Study/Technology
---
[36|Normal] Accurate local weather prediction has been identified as a critical requirement for communities, small farms, and outdoor operations. Traditional forecasting relies on numerical weather prediction models run on macro-scale supercomputers. These models divide the atmosphere into large computational grids (15 to 25 km wide). While effective for broad synoptic fronts, they consistently fail to capture sharp, localized microclimate changes—such as rapid afternoon convective cloudbursts or sudden humidity spikes. Furthermore, modern connected weather stations depend entirely on third-party cloud platforms (e.g., AWS, Weather Underground). During severe storms, broadband internet and cellular communication towers frequently experience outages. When severe weather strikes, cloud-dependent systems become completely unusable. An intelligent edge-server architecture is essential so that environmental monitoring, machine learning inference, and predictive alerts function reliably within the local network.

[42|Normal] Motivation behind the Study

[43|Normal] The drive behind this project is to apply accessible, low-cost Internet of Things (IoT) hardware and state-of-the-art Machine Learning toward an environmental challenge we encounter constantly. Basic DIY weather projects typically read only temperature and display it on an LCD. However, physical meteorology tells us that rain is governed by thermodynamic rate-of-change dynamics: rapid barometric drops (ΔP/Δt) and relative humidity saturation. Processing machine learning locally on a Python Flask edge server rather than costly cloud APIs provides ultra-low latency, zero recurring API expenses, and enables an automated online self-learning loop that continually improves as seasons change.

[63|Normal] 3.1 Problem Statement
---
[64|Normal] Traditional weather apps rely on generalized regional radars that fail to detect hyper-local storms, and modern smart weather gadgets depend completely on third-party cloud hosting which introduces latency, subscription fees, and catastrophic failures during stormy internet cutouts. Furthermore, hobbyist weather stations measure only raw instantaneous temperature and humidity, completely ignoring barometric pressure trends which are the primary physical indicators of approaching precipitation.
Our system addresses this problem through an integrated edge-server IoT pipeline that combines:
• Dedicated Sensor Hub: An Arduino Uno reading physical DHT11 and BMP280 sensors on a stable 1-minute cycle.
• Wi-Fi Gateway: An ESP32 DevKit V1 that receives UART telemetry from the Uno and forwards JSON packets to a local server over Wi-Fi.
• Edge AI & Self-Training Server: A Python Flask server hosting a Machine Learning model (SGDClassifier) that calculates 3h/6h pressure trends, delivers real-time predictions, and dynamically updates its own weights every 6 hours using observed ground truth (online incremental learning).

[69|Normal] 3.3 METHODOLOGY
---
[70|Normal] The underlying architecture is decentralized and edge-server based. The Arduino Uno serves as the frontline sensory node, interfacing with the DHT11 and BMP280. It streams JSON packets directly via UART (Pin 11 TX to GPIO 16 RX2) to the ESP32 with common ground reference. The ESP32 acts as an IoT Wi-Fi gateway that transmits HTTP POST packets over the local 2.4 GHz Wi-Fi network to the laptop edge server. The Python Flask server (server.py) executes the machine learning model, calculates atmospheric derivatives, returns prediction and alert flags to the ESP32, and performs autonomous online self-learning every 6 hours by evaluating past forecasts against real outdoor observations.

[107|Normal] 3.6 Modules
---
[108|Normal] 1. Data Acquisition and Sensor Module: Essentially used to record real-time environmental data; this module serves as the primary sensory organ of our system. Connected to the Arduino Uno, the DHT11 digital sensor captures ambient temperature and relative humidity, while the Bosch BMP280 barometric sensor samples atmospheric pressure via I2C with 16x oversampling and internal IIR filtering to eliminate thermal noise. Every 60,000 ms (1 minute), the Uno packages the filtered metrics into a compact JSON string.
---
[109|Normal] 2. Inter-Board Direct UART Telemetry Module: Connects the Arduino Uno to the ESP32 gateway over a direct serial interface. SoftwareSerial on Arduino Uno (Pin 11 TX) transmits directly to ESP32 HardwareSerial2 (GPIO 16 RX2), and Uno Pin 10 (RX) connects to ESP32 GPIO 17 (TX2), bound by a common system ground. The communication operates cleanly at 9600 baud streaming structured JSON packets without packet loss.
---
[110|Normal] 3. IoT Gateway and Networking Module: Runs on the ESP32, which connects to the local 2.4 GHz Wi-Fi network. Every minute, upon receiving a JSON packet from the Uno, the ESP32 issues an HTTP POST request to the laptop server (http://<LAPTOP_IP>:5000/api/weather). It parses the JSON reply, receiving real-time prediction and rain probability flags.
---
[111|Normal] 4. Edge Server Machine Learning Module: Hosted on the laptop via a Python Flask server (server.py), this module acts as the computational brain. It maintains a 24-hour circular buffer (1440 samples) to calculate 3-hour and 6-hour pressure drops (ΔP_3h, ΔP_6h) and humidity shifts (ΔRH_3h). An SGDClassifier model with log-loss evaluates the scaled 6-dimensional feature vector, predicting upcoming weather (Clear, Cloudy, Rain) and outputting calibrated probabilities in under 15 milliseconds.
---
[112|Normal] 5. Continuous Online Self-Learning & Dashboard Module: To ensure the model remains accurate as seasons transition, this module compares past forecasts against real outdoor observations every 6 hours. It executes incremental online learning using model.partial_fit(), adapting weights dynamically without requiring complete offline retraining. It also provides an interactive web dashboard on localhost:5000 displaying real-time gauges, trend charts, and future date forecasts.

[116|Normal] 4.1 Data Collection
---
[117|Normal] A download_data.py script was used to curate 3 complete years of hourly meteorological data (26,280 samples) from the Open-Meteo Historical Archive for local coordinates (Chennai, Lat: 13.0827°N, Lon: 80.2707°E). The raw dataset included hourly temperature, relative humidity, surface pressure, precipitation amount, and cloud cover. Features were engineered to capture thermodynamic rate-of-change dynamics: 3-hour barometric drop (delta_p_3h), 6-hour barometric drop (delta_p_6h), and 3-hour humidity shift (delta_rh_3h). Target labels were defined 6 hours into the future: 'Rain' (cumulative rain > 0.2 mm), 'Cloudy' (cloud cover ≥ 60%), and 'Clear' otherwise.

[136|Normal] 5.1 Research Findings and Conclusion
---
[137|Normal] The project successfully demonstrates an end-to-end edge-server architecture for localized weather forecasting using an Arduino Uno, an ESP32 gateway, and a self-training Python Flask server. By decoupling hardware acquisition from machine learning computation, the system overcomes the primary weaknesses of existing commercial solutions: reliance on broad 25 km satellite grids and vulnerability to internet cutouts.

Key Research Findings:
1. High Predictive Accuracy: The machine learning model achieves an overall accuracy of 86.4% on validation data (reaching 90.8% in testing), significantly outperforming traditional Zambretti barometric equations (~64%).
2. Effective Storm Detection: The system achieves a 92.3% recall in detecting incoming rainfall events, reliably identifying the sharp pressure drops and humidity surges that precede local storms.
3. Real-Time Edge Operation: Transmitting lightweight JSON telemetry over local Wi-Fi allows complete inference and alert response within 15 milliseconds, eliminating cloud API latency and recurring costs.
4. Automated Continual Self-Learning: The implementation of automated ground-truth verification and incremental training (model.partial_fit()) every 6 hours successfully adapts model weights to shifting seasonal weather patterns without manual intervention.

def handle_weather_telemetry():
    data = request.get_json(force=True)
    temp = float(data.get('temp', 0.0))
    humidity = float(data.get('humidity', 0.0))
    pressure = float(data.get('pressure', 0.0))

    history.append({'time': time.time(), 'temp': temp, 'humidity': humidity, 'pressure': pressure})
    if len(history) > 1440: history.pop(0) # 24-hour circular buffer

    dp3, dp6, drh3 = calculate_trends()
    features = [temp, humidity, pressure, dp3, dp6, drh3]
    scaled = scaler.transform(pd.DataFrame([features], columns=FEATURE_COLS))

    pred = str(model.predict(scaled)[0])
    probs = model.predict_proba(scaled)[0]
    prob_dict = {str(model.classes_[i]): round(float(probs[i]) * 100, 1) for i in range(len(model.classes_))}
    rain_prob = prob_dict.get('Rain', 0.0)
    alert_trigger = (rain_prob >= 60.0)

    return jsonify({
        'status': 'success',
        'prediction': pred,
        'rain_probability': rain_prob,
        'alert': alert_trigger
    })

def online_self_learning_update(actual_weather, past_features):

    model.partial_fit(scaled_sample, [actual_weather])

void sendTelemetryToLaptop(String jsonPayload) {
  HTTPClient http;
  http.begin("http://192.168.1.100:5000/api/weather");
  http.addHeader("Content-Type", "application/json");
  int httpResponseCode = http.POST(jsonPayload);

  if (httpResponseCode == 200) {
    String response = http.getString();
    StaticJsonDocument<512> doc;
    deserializeJson(doc, response);
    bool alert = doc["alert"];
    const char* pred = doc["prediction"];
    float rainProb = doc["rain_probability"];
    Serial.printf("Forecast: %s (Rain: %.1f%%, Alert: %d)\n", pred, rainProb, alert);
  }
  http.end();
}

  }
